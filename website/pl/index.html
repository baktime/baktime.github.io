Bezpłatny szablon open source

Prosty backup.Na GitHubie.

Ustal harmonogram, a GitHub Actions zadba o kopie Twoich baz danych i plików. Każda kopia trafia po zaszyfrowaniu do Twojego magazynu. Nie potrzebujesz osobnego serwera do backupu.

Dlaczego baktime

Backup, który konfigurujesz raz i przestajesz o nim myśleć. Bez serwera, bez abonamentu, bez uzależnienia od dostawcy: dane trafiają do Twojego magazynu.

Banalna konfiguracja

Jeden sekret JSON na bazę danych lub katalog. Nie instalujesz agentów, nie utrzymujesz serwera kopii ani panelu.

Działa na GitHubie

Zadania wykonuje GitHub Actions na swoich maszynach. W prywatnym repozytorium zostaje konfiguracja i historia kopii.

Za darmo

Szablon jest open source. Mała instalacja zwykle mieści się w darmowych limitach GitHub Actions, Cloudflare R2 i Workers. Zobacz szczegóły.

Bezpieczny

restic szyfruje każdą kopię przed wysłaniem. Adresy, hasła i klucze trzymasz w sekretach GitHuba, nigdy w repozytorium.

Szybki i przyrostowy

Zrzut bazy płynie prosto do restic. Pliki są kopiowane na samym serwerze. Po pierwszej kopii wysyłane są tylko zmienione bloki.

Powiadomienia, jak chcesz

Wiadomość na Discordzie po każdej kopii i cotygodniowy raport. Wolisz e-mail? Włącz powiadomienia GitHuba o nieudanych zadaniach.

Jak to działa

  1. Opisujesz, co kopiowaćDodajesz bazę danych lub katalog jako sekret na GitHubie, razem z harmonogramem cron.
  2. Mały Worker pilnuje czasuDarmowy Cloudflare Worker co pięć minut sprawdza, które kopie są do wykonania.
  3. GitHub Actions uruchamia resticZadanie robi zrzut bazy albo łączy się z Twoim serwerem przez SSH.
  4. Dostajesz kopię i wiadomośćZaszyfrowana kopia trafia do Twojego zasobnika, a wynik do historii i na Discorda.

Twoja pierwsza kopia

Zacznij od jednej bazy danych lub jednego katalogu. W przykładach używamy prywatnego repozytorium na GitHubie i magazynu Cloudflare R2.

Czego potrzebujesz

  • Konta na GitHubie (wystarczy darmowe)
  • Konta Cloudflare na magazyn R2 i harmonogram
  • Bazy PostgreSQL lub MySQL albo serwera z Linuksem dostępnego przez SSH
  • Około 20 minut
Pełna dokumentacja konfiguracji (EN)
  1. Utwórz prywatne repozytorium

    Otwórz szablon na GitHubie, wybierz swoje konto, nadaj repozytorium nazwę my-backups i zaznacz Private. Repozytorium zawiera konfigurację i historię zadań. Same kopie trafiają do Twojego magazynu.

  2. Podłącz magazyn kopii

    Utwórz prywatny zasobnik Cloudflare R2 Standard o nazwie my-backups. Wygeneruj token R2 z uprawnieniem Object Read & Write do tego zasobnika. W istniejącym pliku .baktimerc.yml uzupełnij poniższe pola. Podstaw nazwę konta i repozytorium na GitHubie, identyfikator konta Cloudflare oraz nazwę zasobnika. Zachowaj ustawienia retencji. 

    owner: example-org
repo: my-backups
restic:
  backend: r2
  repository: s3:https://ACCOUNT_ID.r2.cloudflarestorage.com/my-backups
  passwordSecretName: RESTIC_PASSWORD
  accessKeyIdSecretName: R2_ACCESS_KEY_ID
  secretAccessKeySecretName: R2_SECRET_ACCESS_KEY

    W repozytorium otwórz Settings → Secrets and variables → Actions → New repository secret. Dodaj osobno trzy sekrety.

    R2_ACCESS_KEY_ID · R2_SECRET_ACCESS_KEY
    Identyfikator klucza i tajny klucz dostępu wygenerowane z tokenem R2.
    RESTIC_PASSWORD
    Wygeneruj osobne hasło do szyfrowania, np. poleceniem openssl rand -base64 32. Zachowaj je również poza GitHubem. Będzie potrzebne do odczytu każdej kopii.
  3. Wskaż bazę danych lub katalog

    Przykład dla PostgreSQL. Dodaj sekrety SHOP_DB_USER i SHOP_DB_PASSWORD z danymi użytkownika bazy, który ma uprawnienia do odczytu danych. Utwórz jeszcze jeden sekret o nazwie BAKTIME_TARGET_SHOP. Jako wartość wklej poniższy JSON, podmieniając adres i nazwę bazy. Taka konfiguracja tworzy kopię bazy shop codziennie o 02:00 UTC. 

    {
  "type": "postgres",
  "database": "shop",
  "connection": {
    "mode": "direct",
    "host": "db.example.com",
    "port": 5432
  },
  "userSecretName": "SHOP_DB_USER",
  "passwordSecretName": "SHOP_DB_PASSWORD",
  "schedule": "0 2 * * *"
}

    Maszyna GitHub Actions musi mieć połączenie z bazą. Jeśli baza działa w sieci prywatnej, skorzystaj z przykładu tunelu SSH w dokumentacji konfiguracji.

    Przykład dla plików z Linuksa. Aby kopiować /srv/uploads o 03:00 UTC, zapisz prywatny klucz SSH w sekrecie UPLOADS_SSH_KEY. Dodaj klucz publiczny do autoryzowanych kluczy użytkownika backup na serwerze. Zapisz poniższy JSON jako sekret BAKTIME_TARGET_UPLOADS, podmieniając adres, użytkownika i ścieżkę. 

    {
  "type": "files",
  "host": "files.example.com",
  "sshUser": "backup",
  "sshKeySecretName": "UPLOADS_SSH_KEY",
  "paths": ["/srv/uploads"],
  "schedule": "0 3 * * *"
}
  4. Uruchom zadanie i sprawdź kopię

    Zapisz konfigurację na gałęzi main. Wybierz Actions → Backup → Run workflow. Nowe źródło zostanie skopiowane od razu. Kolejne ręczne uruchomienia obejmują źródła, dla których nadszedł już termin kopii.

    Dla przykładowej bazy otwórz plik history/shop.yml. Odszukaj wpis status: success i identyfikator snapshotId. Po skonfigurowaniu restic z tym samym zasobnikiem i danymi dostępu poniższe polecenie wyświetli zapisane kopie. Sprawdź odtwarzanie na osobnej bazie testowej zgodnie z instrukcją. Odtworzenie bazy nadpisuje dane w wybranej bazie docelowej. 

    restic snapshots --tag shop
  5. Włącz harmonogram

    Do automatycznych kopii utwórz w Cloudflare przestrzeń Workers KV o nazwie BAKTIME_SCHEDULES. W pliku cloudflare-worker/wrangler.toml wpisz jej identyfikator w istniejącym bloku [[kv_namespaces]]. Ustaw GITHUB_OWNER i GITHUB_REPO na właściciela i nazwę prywatnego repozytorium.

    Dodaj trzy sekrety Actions: CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_API_TOKEN (token z uprawnieniami do wdrażania Workers i zapisu w KV) oraz GH_PAT (token GitHuba typu fine-grained, wyłącznie dla tego repozytorium, z uprawnieniem Contents: Read and write).

    Zapisz konfigurację Workera na gałęzi main. W zakładce Actions poczekaj, aż Deploy Cloudflare Worker zakończy się sukcesem. Następnie uruchom Sync Cloudflare schedule manifest. Worker co pięć minut sprawdza terminy i zleca GitHub Actions wykonanie kopii.

  6. Wybierz sposób powiadamiania

    Discord. W ustawieniach kanału otwórz Integracje → Webhooki i utwórz webhook. Dodaj w repozytorium sekret NOTIFICATION_DISCORD o wartości true. Adres webhooka wklej do sekretu NOTIFICATION_DISCORD_WEBHOOK_URL. Aby wysłać raport testowy, uruchom w Actions zadanie Weekly backup summary.

    E-mail lub GitHub. Aby dostawać wyniki uruchomionych przez Ciebie zadań, w ustawieniach powiadomień GitHuba wybierz System → Actions, a następnie Email lub On GitHub. Możesz ograniczyć te wiadomości do nieudanych zadań.

Czy to jest darmowe?

Szablon jest bezpłatny. Prywatna instancja może działać za darmo, jeśli czas pracy GitHub Actions, użycie Workers i KV oraz rozmiar i liczba operacji w R2 Standard mieszczą się w limitach Twoich planów.

Domyślna synchronizacja harmonogramu uruchamia się co 15 minut, nawet przy jednej kopii dziennie. Aby zużywać mniej minut Actions, w .github/workflows/sync-cloudflare-schedule.yml ustaw cron 17 * * * * na synchronizację raz na godzinę. Po edycji źródła możesz zsynchronizować je ręcznie. Worker nadal sprawdza terminy kopii co pięć minut.
